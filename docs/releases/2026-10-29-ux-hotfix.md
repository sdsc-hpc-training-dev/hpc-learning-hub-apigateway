## 1. Laptop: Backup and Additive Migration

Use PowerShell 7 (`pwsh`). These commands read the existing protected credential
file without printing it. The migration asks for `APPLY FEEDBACK` confirmation.

```powershell
Set-Location 'C:\Users\ofgar\OneDrive\Documents\Interactive video\_prod_readiness\2026-10-29\ux-hotfix'
.\prepare-local-db.ps1 -BackupOnly
.\production-database.ps1 -Operation Migrate
.\production-database.ps1 -Operation Check
```

Only `site_feedback` and its migration record are added. A new restricted role
`learning_hub_gateway_ux_v1` reads the public catalog and curated paths and can
only INSERT feedback. It cannot SELECT/UPDATE/DELETE feedback, change catalog
data, create schema objects, read private user tables, or administer PostgreSQL.
The ingestion identity and all existing credentials remain unchanged.

The new runtime credential file stays in the protected laptop directory and
must never be committed, pasted into chat, or included in the public bundle.
Retain it for controlled retries; do not generate a different password after
the database role already exists.

## 3. VM: Check and Apply

Run as the ordinary login user, not `sudo bash`. The script invokes sudo only
for permitted individual commands. A brief production restart is expected.

```bash
bash
cd /var/tmp/learninghub-ux-hotfix-20261029/bundle
sudo install -o root -g root -m 0600 ../runtime.env /etc/learning-hub/gateway-runtime-ux.env
rm -- ../runtime.env
sha256sum --check SHA256SUMS
bash deploy-production-ux-hotfix.sh --check
```

Stop on any failure. The check verifies the live patched baselines, original
Compose stack, health, Nginx, TLS database connectivity, restricted runtime
identity, and the exact privilege matrix. It does not replace containers.
If Nginx already has a rate limiter, its inheritance needs explicit review.

After confirming the fresh backup and that no production poller was enabled:

```bash
LEARNINGHUB_PROD_POLLERS_CONFIRMED_OFF=yes LEARNINGHUB_FRESH_BACKUP_CONFIRMED=yes bash deploy-production-ux-hotfix.sh --apply
sudo docker ps
curl --fail --max-time 20 --resolve learning-hub.sdsc.edu:443:127.0.0.1 -I https://learning-hub.sdsc.edu/
```

The script loads the exact images without pulling/building. It appends an image
and runtime-credential overlay, preserves ports/resource limits/original env
files, and adds only the feedback rate limiter. It does not touch dev services,
TLS certificates, firewall rules, daily ingestion, or unrelated Nginx routes.

## Rollback

The retained release includes the rollback script and every small verified input;
the original upload directory is not required. Run as your ordinary VM user:

```bash
bash /srv/learning-hub/releases/ux-hotfix-20261029-d10833c2-9c2f66ed/deploy-production-ux-hotfix.sh --rollback
```

This restores the previous security-patched images and removes only this release's
unchanged Nginx limiter. It retains `site_feedback` and genuine responses. Do not
drop the table or delete old images/env files during rollback.

## Private Staff Export and Retention

No public feedback-reading endpoint exists. Authorized staff use the original
elevated environment, not the INSERT-only runtime environment. Run on the VM:

```bash
sudo install -d -o root -g root -m 0700 /srv/learning-hub/feedback-exports
stamp=$(date -u +%Y%m%dT%H%M%SZ)
name="learninghub-feedback-export-$stamp"
sudo docker create --name "$name" --env-file /etc/learning-hub/gateway.env --cap-drop ALL --security-opt no-new-privileges --memory 128m --entrypoint node hpc-learning-hub/gateway:ux-hotfix-20261029-d10833c2 dist/database/feedback-maintenance.js export /tmp/feedback.csv
sudo docker start -a "$name"
sudo docker cp "$name:/tmp/feedback.csv" "/srv/learning-hub/feedback-exports/feedback-$stamp.csv"
sudo chmod 0600 "/srv/learning-hub/feedback-exports/feedback-$stamp.csv"
sudo docker rm "$name"
```

CSV cells escape spreadsheet formulas and preserve ISO timestamps. Keep exports
private; do not upload answers to GitHub, analytics, or AI agents. The local test
verified CSV parsing, formula defense, and preservation of recent responses.

Run this maintenance command monthly to remove database responses older than
12 months. No automatic cronjob is installed by this hotfix:

```bash
sudo docker run --rm --env-file /etc/learning-hub/gateway.env --cap-drop ALL --security-opt no-new-privileges --memory 128m --entrypoint node hpc-learning-hub/gateway:ux-hotfix-20261029-d10833c2 dist/database/feedback-maintenance.js purge
```

Apply the same 12-month retention to exported files. Backups remain subject to
the organization's separate backup retention policy. Existing infrastructure
access logs are separate; survey records contain no identity/tracking columns.
