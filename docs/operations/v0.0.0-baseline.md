# v0.0.0 integration baseline

The standing branches are `master` (released source) and `dev` (integration).
The `v0.0.0` tag records the merged production-readiness and existing development
work. Creating this release does not redeploy the running SDSC VM or change its
database. Refer to the release notes for the paired Gateway/frontend commits.

## Continue existing work

Keep your current feature branch and any uncommitted changes. Commit or stash
those changes before merging the updated integration branch:

```bash
git fetch origin --prune
git switch feature/your-existing-work
git merge origin/dev
```

Resolve conflicts while preserving the catalog caching, bounded pagination,
source-text cleanup, public-feature boundary and accessibility changes. Run the
repository checks and open your feature PR into `dev`. Do not force-push someone
else's branch. Unmerged CILogon, frontend-authentication, Umami and E2E work is not
silently included in this release or deleted during cleanup.

## Start new work

```bash
git fetch origin --prune
git switch dev
git pull --ff-only origin dev
git switch -c feature/your-new-work
```

Use `feature/* -> dev -> release/vX.Y.Z -> master`, then merge release fixes back
into `dev`. Both repositories use the same release tag but have distinct commit
SHAs. Publish paired immutable image digests only after tests pass. Never infer
that a branch update alone changed the containers currently running on train.

The Gateway's former `main` branch is renamed to `master`. Update local tracking
branches, open PR targets and any external automation that still references
`main`. The data-pipeline repository is outside this branch cleanup.
